1.1 ICP备案 vs ICP许可证：自营与平台的本质区别

没有其他机构或个人以自身名义入驻销售，那么办理ICP备案即可。2026年工信部备案表也明确，小程序、快应用在填写备案信息时无需填写域名列表和公钥MD5。

ICP许可证（增值电信业务经营许可证）适用于经营性互联网信息服务。如果平台涉及以下任一模式，需要评估是否申<img width="1684" height="830" alt="9b2a37c02180e8bee15002e9cb152625" src="https://github.com/user-attachments/assets/7ffee9ce-33ec-4a64-aa7e-008809f0f850" />

允许多个入驻方（教师、机构）以自身名义销售课程，平台提供交易场所并抽成；

平台为其他经营者的课程提供在线数据处理与交易处理服务；

业务实质属于“为他人提供平台服务”。

宁波律协的合规指引明确了一条关键判断标准：“企业利用自身APP并以自营方式直接销售自身或其它企业的商品或服务，无其它单位或个人以自身名义入驻该APP实施销售行为的，无需办理ICP许可，办理ICP备案即可。”

1.2 在线视频课程：需要教育类目专项资质
如果小程序或APP提供网课、在线培训、讲座等教育类视频或直播服务，微信小程序类目审核会要求提供以下资质之一：

培训机构：《民办学校办学许可证》《非学科类校外培训机构培训许可证》或《文化艺术类校外培训机构审核意见书》；

全国校外教育培训监管与服务综合平台备案；

教育部门的批准文件；

《信息网络传播视听节目许可证》。

1.3 职业培训类：非政府平台的资质替代方案
如果定位是职业技能培训平台（非学历教育），支付宝小程序类目要求提供职业培训资质；若无该资质，需提供培训合作方授权证明/业务合同，同时提供合作方的持牌资料。

二、系统安全：源码买回来先跑一遍漏洞扫描
知识付费类小程序源码的安全风险被严重低估。一个被公开披露的典型案例是“知识吾爱纯净版小程序系统”——这是一款基于微信小程序平台开发的知识付费应用，被安全研究者发现存在SQL注入漏洞（XVE-2024-30663）。

漏洞的影响范围：攻击者可以利用SQL注入“获取数据库中的信息（例如，管理员后台密码、站点的用户个人信息）”，高权限情况下可向服务器写入木马，进一步获取服务器系统权限。这意味着用户数据、支付信息、后台管理权限全部暴露。

这个案例的信号很明确：低价知识付费源码的安全质量参差不齐。购买源码后，上线前至少需要完成：

代码安全审计：检查SQL查询是否使用参数化、输入是否过滤、文件上传是否受控；

渗透测试：模拟攻击者尝试注入、越权、敏感信息泄露；

已知漏洞排查：用源码名称、版本号搜索CVE、CNVD等漏洞库，确认是否存在已公开的漏洞。

三、个人信息保护：教育场景有专项标准
知识付费/教育类小程序处理的是学员个人信息、手机号、学习记录、支付数据，属于高敏感数据。2026年8月实施的YD/T 6777-2026《电信和互联网服务 用户个人信息保护技术要求 互联网教育服务》 为这一场景提供了专项标准，规定了教育服务过程中个人信息收集、存储、加工、使用等全生命周期的保护要求。

对源码购买者的实际影响：

最小必要原则：报名课程只需手机号，不应强制要求填写职业、收入、身份证号等无关信息；

隐私政策弹窗：首次启动时必须弹窗展示并获取用户主动同意；

数据删除权：用户应能注销账号并删除个人信息；

未成年人保护：如果涉及K12用户，受《未成年人个人信息网络保护规定》更严格约束。

如果源码没有内置隐私政策页面、授权弹窗、账号注销功能，需要在上线前补齐。教育平台合规分析也建议，“教育平台合规建设不是等平台上线后再补办资质，而是在产品设计阶段同步规划”。

四、购买源码前的合规自查清单
业务模式层面：平台是自营（只有自己的课程）还是聚合（多家机构入驻）？聚合模式需要ICP许可证+合作机构资质。

课程内容层面：是否包含在线视频课程/直播？如果是，需要教育类目专项资质。

源码安全层面：要求卖家提供代码安全声明，或自行安排渗透测试。检查是否使用参数化查询、是否有文件上传过滤、后台管理入口是否暴露。

合规功能层面：源码是否内置隐私政策弹窗？是否支持用户账号注销和数据删除？是否支持游客模式浏览课程（无需登录即可查看课程列表）？

备案层面：小程序对应的服务器域名是否已完成ICP备案？APP是否已完成APP备案？
